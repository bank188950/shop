# หน้าร้านลูกค้า — สถานะการพัฒนาปัจจุบัน

## ขอบเขต

เอกสารนี้บันทึกหน้าร้านสำหรับลูกค้าตามที่พัฒนาอยู่ในปัจจุบัน เส้นทางคือ `/` ใน `frontend/` และสร้างด้วย React, Tailwind CSS, Zustand, Lucide icons และ Swiper

หน้านี้นำเสนอ **ลูกชิ้นทอดล้อเลื่อน** ในบรรยากาศอบอุ่น เน้นอาหารเป็นหลัก เนื้อหาถูกจำกัดความกว้างสูงสุด 1488px มีระยะห่างด้านข้าง 24px บนจอใหญ่ และ 14px บนจอเล็ก ส่วน footer และแถบประกาศขยายเต็มความกว้างของ viewport

| --- | --- | --- |

| `canvas` | `#FFFDF9` | พื้นหลังหน้าและพื้นผิว header |
| `ink` | `#183326` | สีข้อความหลัก |
| `muted` | `#455A64` | ข้อความรองและข้อมูลประกอบ |
| `morning` | `#E3F2FD` | การ์ดช่วงเช้า |
| `afternoon` | `#FFF3E0` | การ์ดช่วงบ่าย |
| `brown` | `#76503A` | ปุ่มเข้าสู่ระบบและปุ่มสรุปรายการสั่งซื้อ |

หัวข้อใช้ฟอนต์ Kanit และข้อความประกอบใช้ Sarabun หน้าร้านใช้ขนาดตัวอักษรตั้งแต่ 12px ถึงหัวข้อ section แบบ responsive ที่ 32–48px

## โครงสร้างหน้า

1. **Header** — header สี `canvas` พร้อมเส้นขอบด้านล่าง สูง 92px บนจอใหญ่และ 74px บนจอเล็ก Brand lockup ประกอบด้วยโลโก้ทรงกลม, `ลูกชิ้นทอดล้อเลื่อน` และคำโปรย `อาหารสดใหม่จากกระทะทุกวัน` ด้านขวามีไอคอนดูข้อความจากร้านค้าที่ไปยัง `/my-chats`, ไอคอนออเดอร์ของฉันที่ไปยัง `/my-orders` และไอคอนตะกร้าสีเขียวพร้อม badge จำนวนรายการเมื่อมีสินค้า เมื่อกดตะกร้าจะแสดงเมนู toggle พร้อม thumbnail ชื่อ จำนวนสินค้า ยอดชำระสุทธิ ปุ่มกากบาท และปุ่มไปยังหน้าสรุปรายการสั่งซื้อ; เมนูปิดเมื่อกดกากบาท คลิกภายนอก หรือกด Escape ถัดไปเป็นปุ่ม `สมัครสมาชิก` และปุ่ม `เข้าสู่ระบบ` สีน้ำตาล ซึ่งเปิด modal จาก shadcn/ui บนจอเล็กทั้งสองปุ่มจะแสดงเฉพาะไอคอนแต่มี accessible label; เมื่อเข้าสู่ระบบแล้ว ปุ่มทั้งสองจะถูกแทนที่ด้วยคำทักทายพร้อมชื่อลูกค้า (ซ่อนบนจอเล็ก), ปุ่ม `จัดการ` ที่ไปยัง `/my-profile` (หน้าแก้ไขข้อมูลผู้ใช้ ประกอบด้วยชื่อลูกค้า เบอร์โทรศัพท์ สถานที่ส่งของ และ LINE ID ที่ไม่บังคับ กว้างสูงสุด 960px เท่าหน้าออเดอร์ของฉัน บันทึกผ่าน API `/user/profile` และแสดงแถบยืนยันเมื่อบันทึกสำเร็จ) และปุ่ม `ออกจากระบบ` เรียงตามลำดับ ทั้งสองปุ่มเป็นสีน้ำตาลรูปแบบเดียวกันและแสดงเฉพาะไอคอนบนจอเล็ก
2. **Announcement bar** — ticker สีเขียวเข้มสูง 56px พร้อมไอคอนโทรโข่งที่ตรึงตำแหน่ง แสดงข้อความคำสั่งซื้อล่าสุด 3 รายการจากขวาไปซ้ายเพียงหนึ่งรอบด้วย CSS animation ความยาว 30 วินาที เมื่อข้อความออกจากด้านซ้ายครบแล้วจะแสดงเฉพาะข้อความ `โปรโมชั่น ซื้อลูกชิ้น 10 ไม้ แถมฟรี 1 ไม้` สีเหลืองแบบกะพริบ พร้อมจุดคั่นหน้าและหลัง เป็นเวลา 16 วินาที ก่อนวนกลับไปที่รายการสั่งซื้อ จึงไม่มีข้อความคำสั่งซื้อและโปรโมชันปรากฏพร้อมกัน และมีข้อความเวอร์ชันสำหรับ screen reader การเคลื่อนไหวจะหยุดเมื่อเปิด `prefers-reduced-motion` หรือวางเมาส์เหนือแถบประกาศ
3. **Hero** — Swiper carousel แบบมุมโค้ง 2 สไลด์ ใช้ `hero-truck-clean-grille.png` และ `hero-fried-snacks-drinks.png` รูปสูง 520px บนจอใหญ่ และ 260px บนจอเล็ก เปลี่ยนภาพแบบ fade 1000ms, วนลูป, รองรับ keyboard และ touch swipe, แสดง pagination dot และเล่นอัตโนมัติทุก 7 วินาที เว้นแต่ผู้ใช้เลือก reduced motion ไม่มีข้อความหรือ call to action วางทับภาพ
4. **Recent orders** — เว้นระยะใต้ hero 40px บน desktop / 28px บนจอเล็ก มีไอคอนตารางและหัวข้อ `รายการสั่งซื้อ` ตามด้วยข้อมูลตัวอย่าง 12 รายการ ตารางใช้หัวสีเขียว มีคอลัมน์ `ชื่อลูกค้า`, `รายการที่สั่ง`, `ช่วงเวลา`, `สั่งเมื่อ`, `จำนวนเงิน` และ `ชำระเงิน` ตารางมีความกว้างเนื้อหาขั้นต่ำ 1040px และเลื่อนแนวนอนบนจอแคบ แสดงครั้งละ 5 รายการ รวม 3 หน้า พร้อมปุ่มก่อนหน้า/ถัดไปและปุ่มเลขหน้า
5. **Menu** — ใช้ไอคอนหมวกเชฟและหัวข้อ `เลือกเมนูที่ชอบ` มีแท็บ `ทั้งหมด` ตามด้วยหมวดสินค้าจาก API `/user/product-categories` ซึ่งคืนเฉพาะหมวดที่เปิดใช้งานและมีสินค้าอยู่จริง โดย `ทั้งหมด` ถูกเลือกตอนเริ่มต้น การเลือกแท็บเปลี่ยนหน้าตา ค่า `aria-selected` และกรองการ์ดสินค้าตามหมวดที่เลือกจริง; ระหว่างโหลดแสดงข้อความ `กำลังโหลดเมนู...` และเมื่อหมวดนั้นไม่มีสินค้าแสดง `ยังไม่มีเมนูในหมวดนี้` Grid เป็น 4 คอลัมน์บนจอใหญ่ และ 2 คอลัมน์เมื่อความกว้างต่ำกว่า breakpoint `lg`
6. **Sticky cart** — แถบลอยสีเขียวเข้มใกล้ขอบล่างของ viewport กว้างสูงสุด 1440px แสดงจำนวนสินค้าและยอดรวม พร้อมปุ่ม `ดูรายการสั่งซื้อ` สีน้ำตาล ปุ่มจะ disabled เมื่อตะกร้าว่างโดยยังคงพื้นผิวสีน้ำตาลแบบลด contrast และนำผู้ใช้ไปที่ `/order-summary` เมื่อตะกร้ามีสินค้า ตะกร้าที่ persist จะเริ่มต้นด้วยไส้กรอกอีสานย่าง 1 รายการ
7. **Footer** — footer สีเขียวเข้มเต็มความกว้าง จัดเนื้อหากึ่งกลาง แสดงโลโก้สีขาว ชื่อแบรนด์ ลิงก์ช่วงเวลาจัดส่ง และ `© 2026 ลูกชิ้นทอดล้อเลื่อน - By Tawatchai`
8. **My orders** — เส้นทาง `/my-orders` ใช้ header/footer เดียวกับหน้าร้าน แสดงออเดอร์ของลูกค้าเป็น card ที่อ่านสถานะ รอบส่ง จุดรับสินค้า รายการ และยอดชำระได้ง่าย
9. **My chats** — เส้นทาง `/my-chats` ใช้ header/footer เดียวกับหน้าร้าน หัวข้อหน้าเป็น `ข้อความจากร้านค้า` แสดงข้อความและรูปภาพที่ร้านค้าส่งถึงลูกค้าปัจจุบันโดยใช้ชื่อผู้ส่งว่า `เจ้าของร้าน` พร้อมวันเวลาส่ง และมีสถานะว่างเมื่อยังไม่มีข้อความ
10. **Notice popup** — เมื่อเข้าหน้าแรกและแอดมินเปิดใช้งานการแจ้งข้อมูลเตือน จะแสดง popup ของ sweetalert2 หัวข้อ `ประกาศแจ้งเตือนจากทางร้าน` พร้อมไอคอนกระดิ่งสีเขียว `brand` เนื้อหาเป็นข้อความที่ตั้งไว้ในหน้า `ตั้งค่า` ของผู้ดูแลโดยคงการขึ้นบรรทัดตามที่พิมพ์ หากยังไม่ได้กรอกข้อความจะแสดงเฉพาะหัวข้อ ไม่มีปุ่มยืนยัน ปิดได้ด้วยปุ่มกากบาท คลิกนอก popup หรือกด Escape; แสดงครั้งเดียวจนกว่าจะปิด browser ทุกหน้าต่าง การรีเฟรชหรือเปิดแท็บใหม่จึงไม่แสดงซ้ำ; จำสถานะไว้ใน `sessionStorage` คีย์ `shop-notice-popup-shown` ซึ่ง browser ล้างให้เองเมื่อปิด และแท็บที่เพิ่งเปิดจะถามแท็บอื่นผ่าน `BroadcastChannel` ชื่อ `shop-notice-popup` ว่ารอบนี้แสดงไปแล้วหรือยัง; ข้อมูลมาจาก API `/user/announcements` ชุดเดียวกับแถบประกาศ ในรูปแบบ `notice.isEnabled` และ `notice.message` โดยยึด `isEnabled` เป็นเงื่อนไขการแสดง

## เนื้อหาและสถานะ

### ตารางคำสั่งซื้อล่าสุด

- ช่วงเช้าใช้ข้อความสีน้ำเงิน และช่วงบ่ายใช้ข้อความสีส้ม
- คอลัมน์ `ชำระเงิน` แสดง `รอชำระเงิน` เป็น badge สีแดงพาสเทล (ข้อความ `#BD3B35`, พื้น `#FFE6E3`) และ `จ่ายแล้ว` เป็น badge สีเขียวพาสเทล; หากแสดงสถานะออเดอร์ด้วย ให้ใช้ `รอตรวจสอบ` เป็นเหลืองพาสเทล (ข้อความ `#9C5127`, พื้น `#FFF0D5`), `เตรียมสินค้า` เป็นม่วงพาสเทล, `กำลังส่ง` เป็นม่วงพาสเทล, `ส่งแล้ว` เป็นเขียวพาสเทล และ `ยกเลิก` เป็นแดงพาสเทลเช่นเดียวกับรอชำระเงิน
- Badge สถานะออเดอร์ของผู้ใช้ทุกตัว รวมถึงหน้า `/my-orders` ต้องแสดงไอคอนที่สื่อความหมายของสถานะเสมอ ควบคู่กับข้อความสถานะ
- ปุ่มแบ่งหน้าเป็น control วงกลมขนาด 44px สถานะ disabled ลดความทึบลง

### แค็ตตาล็อกสินค้า

การ์ดสินค้าดึงจาก API `/user/products` ซึ่งคืนเฉพาะสินค้าที่เปิดใช้งานและอยู่ในหมวดที่เปิดใช้งาน โดยเรียงสินค้าที่ยังมีสต็อกไว้ก่อน ถัดมาคือสินค้าแนะนำ และปิดท้ายด้วยสินค้าที่หมด ป้ายสต็อกกับ badge คำนวณจากข้อมูลจริงตามตารางนี้

| สถานะ | เงื่อนไข | ป้ายสต็อก | Badge | สี |
| --- | --- | --- | --- | --- |
| มีสินค้า | `stock_quantity` มากกว่า `low_stock_threshold` | `เหลือ {จำนวน} {หน่วย}` | มีสินค้า | เขียวหลัก |
| ใกล้หมด | `stock_quantity` มากกว่า 0 แต่ไม่เกิน `low_stock_threshold` | `เหลือ {จำนวน} {หน่วย}` | ใกล้หมด | ส้ม |
| สินค้าหมด | `stock_quantity` เท่ากับ 0 | `สินค้าหมด` | หมดแล้ว | แดง |

สินค้าที่ตั้งค่าเป็นสินค้าแนะนำแสดงป้าย `แนะนำ` ที่มุมซ้ายบนของภาพ ยกเว้นสินค้าที่หมดจะไม่แสดงป้ายนี้แม้ถูกตั้งเป็นสินค้าแนะนำ สินค้าที่ยังไม่มีรูปจะแสดงไอคอนแทนภาพบนพื้นสีเทาอ่อน การ์ดสินค้าที่พร้อมขายยกตัวและมีเงาเล็กน้อยเมื่อ hover ส่วนปุ่มบวกจะย่อ/ขยายเมื่อกด ป้ายและข้อความสต็อกน้อยเป็นสีส้ม การ์ดสินค้าหมดลดสีและความทึบของภาพ แต่ป้ายและข้อความ `สินค้าหมด` เป็นสีแดง พร้อมปุ่ม unavailable สีเท้าที่ disabled และใช้ไอคอน `Ban` ปุ่มเพิ่มสินค้าขนาด 42px บนจอใหญ่ และ 36px บนจอเล็ก

### พฤติกรรมตะกร้า

- ข้อมูลตะกร้าถูก persist ใน browser storage ด้วยคีย์ `lookchin-cart-v2`
- การเพิ่มสินค้าเดิมจะเพิ่ม quantity แทนการสร้างแถวใหม่ในตะกร้า
- ยอดรวมคำนวณจากราคาของสินค้าแต่ละรายการคูณ quantity
- ปุ่มสรุปรายการสั่งซื้อนำไปยังหน้า `/order-summary`; ผู้ใช้ต้องเข้าสู่ระบบและเลือกรอบการสั่งซื้อก่อนจึงกดยืนยันได้ ข้อมูลผู้รับดึงจากบัญชีที่เข้าสู่ระบบ และใช้สถานที่ส่งของที่ตั้งไว้ในบัญชี
- เวลาปิดรับและเวลาจัดส่งของแต่ละรอบดึงจาก API `/user/delivery-settings` ตามค่าที่แอดมินตั้งไว้ รอบที่เลยเวลาปิดรับของวันนี้จะถูก disable และแสดงข้อความ `ปิดรับรอบนี้แล้ว`
- เมื่อกดยืนยันการเลือกสินค้า ระบบจะสร้างคำสั่งซื้อจริงผ่าน `/user/orders` พร้อมตัดสต็อกทันทีใน transaction เดียวกัน สถานะเริ่มต้นคือ `pending_payment` (รอชำระเงิน) จากนั้นตะกร้าจะถูกล้างและหน้าจะเปลี่ยนเป็นโหมดอ่านอย่างเดียวพร้อมแสดงเลขที่คำสั่งซื้อ
- QR พร้อมเพย์สำหรับชำระเงินจะแสดงเมื่อสร้างคำสั่งซื้อแล้ว โดย backend สร้าง payload เองจากบัญชีรับเงินในตาราง `settings` พร้อมระบุยอดของคำสั่งซื้อนั้น และแสดงชื่อบัญชีใต้ QR ให้ลูกค้าเทียบกับที่แอปธนาคารขึ้นให้
- ลูกค้าอัปโหลดรูปสลิปเพื่อยืนยันการชำระเงิน ระบบส่งสลิปไปตรวจกับ Slip2Go ตาม `specs/payment-slip-verification.md` เมื่อตรวจผ่าน สถานะจะเปลี่ยนเป็น `paid` และคำสั่งซื้อเข้าสู่ `pending_review` (รอตรวจสอบ) จากนั้นแอดมินจะเดินสถานะต่อเป็นเตรียมสินค้า พร้อมส่ง และส่งแล้วตามลำดับ
- เมื่อตรวจสลิปไม่ผ่าน สถานะคำสั่งซื้อจะไม่เปลี่ยน ระบบแจ้งสาเหตุเป็นภาษาไทยและให้แนบสลิปใหม่ได้ไม่เกิน 3 ครั้งต่อคำสั่งซื้อ เกินกว่านั้นให้ติดต่อแอดมินเพื่อตรวจด้วยตา
- หน้าชำระเงินแจ้งให้ชำระภายใน 20 นาที โดยอ่านค่าจาก `paymentMinutes` ที่ API `/user/settings` ส่งมาจากค่าคงที่ `USER_ORDER_PAYMENT_MINUTES` ข้อความนี้เป็นการเตือนให้ลูกค้ารีบโอนเท่านั้น ปัจจุบันยังไม่มีการยกเลิกคำสั่งซื้อหรือคืนสต็อกอัตโนมัติเมื่อเลยเวลา
- หน้า `/my-orders` แสดงคำสั่งซื้อจริงของบัญชีที่เข้าสู่ระบบ พร้อม badge สถานะการชำระเงินและสถานะคำสั่งซื้อ

## การโต้ตอบ การเคลื่อนไหว และการเข้าถึง

- ปุ่มตะกร้าใน header, ปุ่มเพิ่มสินค้า และปุ่มแบ่งหน้าตาราง มี accessible label เมื่อเป็นปุ่มไอคอน
- ปุ่มตะกร้าใน header มีค่า `aria-expanded` เพื่อบอกสถานะของเมนูตะกร้า
- Modal สมัครสมาชิกมีฟิลด์เบอร์โทรศัพท์ ชื่อลูกค้า LINE ID (ไม่บังคับ กำกับไว้ที่ป้ายกำกับ) สถานที่ส่งของ รหัสผ่าน และยืนยันรหัสผ่าน; modal เข้าสู่ระบบมีเบอร์โทรศัพท์และรหัสผ่าน ทั้งสองฟอร์มตรวจสอบข้อมูลก่อนส่งและแสดงข้อความภาษาไทยใต้ช่องที่กรอกไม่ถูกต้อง และแสดงข้อความผิดพลาดจากเซิร์ฟเวอร์ เช่น เบอร์โทรศัพท์ซ้ำหรือรหัสผ่านไม่ถูกต้อง เป็นแถบสีแดงอ่อนข้อความจัดกึ่งกลาง วางเหนือปุ่มยืนยันของฟอร์ม
- ตัวเลือกสถานที่ส่งของใน modal สมัครสมาชิกดึงจาก API `/user/locations` ซึ่งคืนเฉพาะสถานที่ที่เปิดใช้งาน; เมื่อสมัครสมาชิกหรือเข้าสู่ระบบสำเร็จ modal จะปิดและระบบถือว่าเข้าสู่ระบบแล้วทันที
- keyboard focus ส่วนกลางใช้เส้นขอบสีเขียวหลักขนาด 3px และมี offset 3px
- ปุ่มและการ์ดใช้ transition timing เริ่มต้นของ Tailwind ปุ่มสินค้าที่พร้อมขายมี active scale effect
- การ scroll แบบ smooth และ animation ของ announcement จะถูกปิดหรือลดลงเมื่อเปิด `prefers-reduced-motion` และหยุดชั่วคราวเมื่อ hover แถบประกาศ; hero autoplay ก็ถูกปิดเช่นกัน
- Layout กำหนดความกว้าง `body` ขั้นต่ำ 320px ตารางคำสั่งซื้อและแถว category สามารถเลื่อนแนวนอนได้เมื่อจำเป็น
